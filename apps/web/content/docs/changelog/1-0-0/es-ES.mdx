## Extensión de navegador

La extensión es la primera pieza visible del sistema. Vigila los sitios compatibles, instala el paquete de presence correcto y mantiene la actividad en movimiento hacia el host nativo sin pedir al usuario que gestione la infraestructura.

- Las presences solo se ejecutan en sitios web coincidentes.
- La extensión carga el paquete firmado correcto para la presence.
- La actividad se reenvía a Discord a través del host nativo local.
- El soporte de scripts de usuario está documentado y restringido porque es un permiso sensible.

## Host nativo

El compañero nativo es lo que convierte el estado de la página en un estado real de Discord. Mantiene la capa del navegador enfocada y le da al sistema un punto de entrega limpio.

- Recibe payloads de presences desde la extensión.
- Traduce esos payloads en actualizaciones de Discord Rich Presence.
- Mantiene la conexión de Discord separada de la sesión del navegador.

## Biblioteca y descubrimiento

La biblioteca pública es la superficie del producto que la gente navega antes de instalar algo.

- Cada presence tiene una página de detalle dedicada.
- Las URL compatibles, el historial de versiones, las valoraciones y los comentarios son visibles antes de la instalación.
- Las estadísticas de instalación ayudan a las personas a juzgar si una presence está activa y mantenida.
- Las páginas de presence exponen suficientes metadatos para entender lo que hace la integración antes de que el usuario se comprometa con ella.

## Ciclo de vida de presence

El ciclo de vida es deliberadamente simple y visible para el usuario:

```txt
install -> enable -> update -> disable -> uninstall
```

- Install obtiene la última versión firmada.
- Update mantiene el paquete instalado alineado con la versión publicada.
- Disable detiene la presence sin eliminarla de la lista del usuario.
- Uninstall elimina la presence de la extensión.

## Documentación y onboarding

El primer lanzamiento estable también estableció el material de soporte alrededor del producto.

- El flujo de onboarding explica la relación entre la extensión, el host nativo y las presences.
- La solución de problemas cubre los modos de fallo comunes en lugar de asumir que el usuario puede inferirlos.
- La documentación explica la estructura de una presence y cómo se publica.

## Flujo de trabajo del desarrollador

El lanzamiento es también el punto en el que el proyecto se volvió publicable de forma repetible.

```bash
pnpm presence init "Ejemplo"
pnpm presence validate
pnpm presence build example
pnpm presence push example
```

- La validación de metadatos ayuda a mantener el catálogo consistente.
- El empaquetado y la firma son parte del camino de publicación.
- La CLI ofrece a los colaboradores una forma predecible de crear y enviar presences.

## Por qué `1.0.0` es importante

> Este es el lanzamiento donde el producto se vuelve coherente: la extensión, el host, la biblioteca, los docs y el pipeline de publicación, todo alineado.
