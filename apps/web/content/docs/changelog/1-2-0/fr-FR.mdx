## Lecteur

Le composant `CurrentActivityCard` a été entièrement repensé avec un layout Bar compact. L'état idle affiche un vinyle SVG animé de 48px avec le texte "Aucune activité détectée" en ligne. L'état actif affiche l'artwork en 48×48, le titre, le sous-titre, et un fond flou du poster quand `largeImage` est présent.

Les contrôles média (précédent, lecture/pause, suivant) ont été supprimés — ils ne mettaient pas en pause le média réel et ajoutaient du bruit visuel. La barre de progression est maintenant conditionnelle : seules les présences `music`, `streaming`, `tv` et `anime` l'affichent ; les présences `other` ne l'ont pas.

Un toggle `showPlayer` dans les paramètres d'affichage permet de masquer entièrement la carte du lecteur.

## Sheet

Un composant `Sheet` natif a été créé de zéro en Tailwind v4, sans Radix UI. Il supporte deux positions : un panneau latéral depuis la droite, et un panneau depuis le bas avec bords supérieurs arrondis. Le composant gère l'overlay sombre avec `backdrop-blur`, la fermeture au clic sur l'overlay ou la touche Escape, un focus trap cyclique, la sauvegarde et la restauration du focus précédent, et une animation CSS d'entrée. Une prop `subtitle` optionnelle permet d'afficher un texte secondaire dans l'en-tête.

## Badge d'extension

Le service worker définit un badge `•` quand une présence envoie une activité à Discord. La couleur du badge utilise l'accent Nowly (`#5865F2`). Il se nettoie quand l'activité est effacée.

## Switch et Checkbox personnalisés

Deux composants remplacent les éléments de formulaire natifs du navigateur. Le Switch a un track carré de 18×36px avec `rounded-lg`. OFF : `bg-card-2` avec bordure, bouton gris. ON : `bg-accent`, bouton blanc. La Checkbox fait 18×18px avec `rounded-[5px]`. OFF : `bg-card-2 border-border`. ON : `bg-accent` avec une icône `Check` blanche.

Les deux supportent la prop `id` pour le lien de label via `htmlFor`.

## Snooze

La fonctionnalité snooze permet de mettre en pause l'activité Discord pour une durée définie. Un bottom sheet avec un stepper `[−] [minutes] [+]` (pas de 5 minutes, plage 5–240 minutes) permet une sélection rapide de la durée. Quand le snooze est actif, la barre d'actions affiche une icône Soleil au lieu du Flocon.

Le réveil n'envoie que `CLEAR_ACTIVITY` à Discord — l'activité Nowly reste visible avec un badge "Snoozé". Le désnoozage renvoie l'activité stockée à Discord.

## Planning

Les utilisateurs peuvent définir des plannings par présence ou globalement. Le sheet de planning affiche 7 boutons de jour (Dim–Sam) avec un toggle de plage horaire optionnel. Quand le mode "Toute la journée" est activé, seuls les jours sont sauvegardés — la présence est active toute la journée sur les jours sélectionnés. Quand la plage horaire est active, les heures de début et fin sont affichées.

Le planning global (accessible depuis le bouton Calendar de la barre d'actions) sert de fallback quand aucun planning par présence n'est défini. Un bouton Calendar par présence se trouve à côté de l'icône engrenage sur chaque élément de la liste.

Le planning peut être désactivé via la section "Fonctionnalités supplémentaires" dans les paramètres (`scheduleEnabled` désactivé par défaut), ce qui masque tous les boutons de planning.

## Réorganisation des paramètres

Le panneau des paramètres a été simplifié :
- **Header** : Le statut de connexion est maintenant un bullet coloré + texte de statut. La carte connexion/hôte est supprimée.
- **Carte de mise à jour** : Affichée uniquement quand `hostVersionInfo.updateAvailable` est vrai, stylisée avec une teinte accent (`bg-accent/5`, `border-accent/20`).
- **Gestion des données** : Fusionnée avec le consentement analytics sous une seule carte "Données et confidentialité".
- **Vérifier les mises à jour** : Déplacé du footer d'activité vers la barre d'actions, avec une limite de 30 secondes. Désactivé automatiquement en mode décompressé.
- **Fonctionnalités supplémentaires** : Nouvelle section hébergeant les toggles de fonctionnalités (Planning est le premier).
- **Barre d'actions** : Visible uniquement sur l'onglet Activité — l'onglet Réglages reste dégagé sans boutons d'action.

## Panneau de debug conditionnel

Le `DebugPanel` n'est rendu que dans les extensions **décompressées** (`!chrome.runtime.getManifest().update_url`). Il réside exclusivement dans la vue **Réglages** — la page Activité reste propre. Quand un problème de debug existe (`debug` n'est pas null ou `nativeStatus` n'est pas connecté/ok), l'en-tête du panneau est toujours visible avec une icône Terminal et le label "Debug". En cliquant sur l'en-tête, le panneau se déploie pour afficher les détails de debug et un champ de personnalisation de l'URL de l'API.

Dans les builds Chrome Web Store (`update_url` présent), le panneau de debug n'est jamais rendu.

De plus, **Vérifier les mises à jour** est automatiquement désactivé en mode décompressé — l'appel devient inactif pour éviter les fausses notifications de mise à jour causées par l'absence de métadonnées de version dans les présences en développement.

## Style des présences inactives

Quand une présence est désactivée, son icône devient `opacity-60 saturate-0` et le nom s'estompe en `text-muted-foreground/80` — subtilement atténué mais toujours lisible.

> Cette release transforme Nowly d'un simple gestionnaire de présence en un outil complet avec planification, snooze et une interface raffinée.
