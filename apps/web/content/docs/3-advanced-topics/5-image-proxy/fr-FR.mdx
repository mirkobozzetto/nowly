title: Proxy d’image
description: Utilisez le proxy d’image Nowly lorsque Discord ne peut pas charger directement une image de présence depuis un CDN externe pris en charge.
---

## À quoi ça sert

Le proxy d’image est un outil côté serveur prévu pour certains cas précis : des images publiques, visibles depuis le navigateur, mais que Discord ne parvient pas à récupérer correctement en direct.

C’est utile pour des images comme des miniatures de vidéos, des posters ou des visuels servis par un CDN externe lorsque :

- l’URL de l’image est publique dans le navigateur ;
- Discord refuse, laisse expirer ou n’arrive pas à télécharger l’URL d’origine ;
- la présence a besoin d’une vraie image liée au contenu, plutôt que du logo de la plateforme uniquement.

Ce n’est pas un proxy d’image générique. Il accepte uniquement les origines explicitement prises en charge par l’API Nowly.

## Endpoint

```txt
https://api.nowly.me/image-proxy?service=<service>&url=<url-de-l-image-encodée>
```

Le paramètre `url` doit être encodé avec `encodeURIComponent`. Le paramètre `service` est optionnel, mais recommandé lorsque vous savez quel service pris en charge fournit l’image.

```ts filename="presence.ts"
import { createImageProxyUrl } from "@nowly/presence"

const proxiedImage = createImageProxyUrl("tiktok", imageUrl)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: proxiedImage ?? Assets.Logo,
})
```

## Quand l’utiliser

Utilisez le proxy d’image uniquement lorsqu’une URL d’image normale ne fonctionne pas de manière fiable dans Discord Rich Presence.

Préférez `Assets.Logo`, `Assets.Icon` ou une URL `https://` directe et stable lorsque cela fonctionne. Le proxy est conçu pour les cas particuliers où un CDN externe nécessite une récupération côté serveur, des en-têtes spécifiques ou une validation avant que Discord puisse afficher l’image.

## Mise en place dans une présence

Commencez par récupérer l’URL de l’image depuis la page. Par exemple, pour un poster vidéo :

```ts filename="presence.ts"
function getPoster(video: HTMLVideoElement): string | undefined {
  if (video.poster) return video.poster

  const image = video.closest("[data-video]")?.querySelector("img")
  return image?.getAttribute("src") ?? undefined
}
```

Ensuite, passez cette URL au proxy avant d’envoyer l’activité :

```ts filename="presence.ts"
import { createImageProxyUrl } from "@nowly/presence"

const poster = video ? createImageProxyUrl("tiktok", getPoster(video)) : undefined

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: poster ?? Assets.Logo,
})
```

Gardez toujours un asset de secours afin que la présence continue de fonctionner si la page ne fournit aucune image ou si le proxy refuse l’URL.

## URLs prises en charge

Les domaines autorisés sont vérifiés par l’API, pas par la présence. Si un domaine n’est pas dans la liste d’autorisation, le proxy renvoie une erreur au lieu de télécharger l’image.

Côté API, les services pris en charge sont configurés via des entrées contenant un `id`, des suffixes de domaines autorisés et, si nécessaire, des en-têtes de requête. Cela permet d’ajouter un nouveau service facilement, sans transformer le proxy en proxy public ouvert.

Si votre présence a besoin d’une nouvelle origine d’image, ajoutez l’utilisation du proxy dans votre PR de présence et expliquez :

- les hostnames exacts qui doivent être pris en charge ;
- pourquoi Discord ne peut pas utiliser l’URL directe ;
- quelle image sera affichée à l’utilisateur ;
- pourquoi cette image est publique et peut être proxifiée sans risque.

Les reviewers décideront ensuite s’ils ajoutent ces URLs à la liste prise en charge. Ils peuvent refuser les origines trop larges, instables, privées ou dangereuses.

## Notes de sécurité

Le proxy doit rester limité. Il doit uniquement télécharger des images publiques issues de CDN nécessaires à des présences relues et acceptées.

Ne l’utilisez pas pour des images de comptes privés, des ressources authentifiées, des URLs de tracking, des entrées utilisateur arbitraires ou du contenu qui n’est pas une image.
