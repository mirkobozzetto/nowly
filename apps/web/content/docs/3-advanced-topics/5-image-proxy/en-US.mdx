## What It Is For

The image proxy is a server-side tool for specific cases: public images that are visible in the browser, but that Discord cannot reliably fetch directly.

It is useful for images such as video thumbnails, posters, or assets served by an external CDN when:

- the image URL is public in the browser;
- Discord rejects, expires, or fails to download the original URL;
- the presence needs to show a real content image instead of only the platform logo.

This is not a general-purpose image proxy. It only accepts origins that are explicitly supported by the Nowly API.

## Endpoint

```txt
https://api.nowly.me/image-proxy?service=<service>&url=<encoded-image-url>
```

The `url` parameter must be encoded with `encodeURIComponent`. The `service` parameter is optional, but recommended when you know which supported service owns the image.

Discord also limits image keys to 300 characters. If the final proxy URL would be longer than that, use a short service-specific proxy path instead of passing the full CDN URL.

```ts filename="presence.ts"
import { createImageProxyUrl } from "@nowly/presence"

const proxiedImage = createImageProxyUrl("tiktok", imageUrl)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: proxiedImage ?? Assets.Logo,
})
```

`createImageProxyUrl` returns `undefined` when the generated URL would exceed Discord’s length limit.

## When To Use It

Use the image proxy only when a normal image URL does not work reliably in Discord Rich Presence.

Prefer `Assets.Logo`, `Assets.Icon`, or a direct stable `https://` image URL when those work. The proxy is designed for edge cases where an external CDN needs server-side fetching, specific request headers, or validation before Discord can display the image.

## Setting It Up In A Presence

First, extract the image URL from the page. For example, a video poster:

```ts filename="presence.ts"
function getPoster(video: HTMLVideoElement): string | undefined {
  if (video.poster) return video.poster

  const image = video.closest("[data-video]")?.querySelector("img")
  return image?.getAttribute("src") ?? undefined
}
```

Then pass that URL through the proxy before sending the activity. For services that support short proxy paths, prefer `createImageProxyPath`:

```ts filename="presence.ts"
import { createImageProxyPath } from "@nowly/presence"

const poster = createImageProxyPath("tiktok", "video", handle, videoId)

await presence.setActivity({
  details: "Watching a video",
  largeImageKey: poster ?? Assets.Logo,
})
```

Always keep a fallback asset so the presence still works when the page has no image or the proxy rejects the URL.

For TikTok, the short paths are:

```txt
https://api.nowly.me/image-proxy/tiktok/video/<handle>/<videoId>
https://api.nowly.me/image-proxy/tiktok/profile/<handle>
https://api.nowly.me/image-proxy/tiktok/category/<section>/<category>
```

Those paths let the API resolve the actual CDN image server-side while keeping the Discord `large_image` value short.

The TikTok category path is intended for live category pages such as:

```txt
https://www.tiktok.com/live/category/gaming/Garena_Free_Fire
```

## Supported URLs

Allowed domains are checked by the API, not by the presence. If a domain is not allowlisted, the proxy returns an error instead of downloading the image.

On the API side, supported services are configured as entries with an `id`, allowed host suffixes, and optional request headers. This keeps new services easy to add while avoiding an open public proxy.

If your presence needs a new image origin, include the proxy usage in your presence PR and explain:

- which exact hostnames need support;
- why Discord cannot use the direct image URL;
- what image the user will see;
- why the image is public and safe to proxy.

Reviewers will then decide whether to add those URLs to the supported list. They may reject origins that are too broad, unstable, private, or unsafe.

## Security Notes

The proxy must stay limited. It should only download public CDN images that are needed by reviewed and accepted presences.

Do not use it for private account images, authenticated resources, tracking URLs, arbitrary user input, or non-image content.
